# 内容标准

## 一条总原则

数字化教具必须解决传统板书、静态图片或普通 PPT 难以解决的数学理解问题。不能为了动画而动画，也不能为了交互而交互。

不是每一课时都必须配置 Applet 或 Manim。只有当数字化能显著降低理解难度、暴露动态关系、连接多种表征、支持学生操作诊断，或让教师更好地控制课堂节奏时，才进入资源生产 backlog。若普通板书、教材例题、纸笔练习或静态图已经足够清楚，应保留为教师脚本、学生活动或诊断题，不强行做可视化。

## 数字化必要性门槛

每个 `digital_entry_points` 必须至少满足下列一项，并在 `note` 中说清楚原因：

- 动态变化不可替代：变量连续变化、极限逼近、参数拖动、几何对象运动会揭示静态图难以呈现的不变量或变化规律。
- 多表征联动有价值：符号、图像、表格、几何对象和语言描述需要同步变化，学生容易在表征切换处断裂。
- 认知痛点明确：该资源直接回应一个具体错因或难点，例如方向符号、边界条件、一般式遗漏、参数混淆。
- 操作能产生数学意义：学生拖动、选择或调参后，必须能形成可讨论的观察、猜想、验证或反例。
- 诊断反馈更有效：即时反馈能定位错因，而不只是给出对错。
- 动画叙事有必要：Manim 用于展示连续推演、构造过程或公式来源；若只是把静态板书动起来，不应制作。

不满足上述门槛的内容，不应进入 Applet 或 Manim 生产；可以保留为文本说明、纸笔任务、教师追问或普通诊断题。

## Applet 适用场景

优先使用 HTML 交互 Applet：

- 参数变化：函数图像、圆锥曲线、统计分布。
- 拖拽探索：单位圆、向量、复平面、几何关系。
- 多表征联动：解析式、图像、表格、语言描述同步。
- 模拟实验：概率、抽样、频率稳定、回归残差。
- 学生操作诊断：错误选择、区间判断、参数识别。

## Manim 适用场景

优先使用 Manim 动画：

- 连续推演：割线逼近切线、函数图像生成过程。
- 证明结构：基本不等式、数列求和、数学归纳法。
- 概念导入：单位圆如何生成正弦波、离心率如何改变曲线。
- 公式变形：三角恒等变换、导数法则、递推展开。
- 课堂开场：30 到 90 秒的概念叙事动画。

## 组合策略

```text
Manim 建立直觉
-> Applet 操作验证
-> Student Task 表达结论
-> Diagnosis 暴露误区
-> Teacher Script 回到课堂讲解
```

## 数学公式呈现标准

所有课堂可见的数学表达都必须符合高中数学书写习惯，不能把程序变量名、ASCII 占位或横向文本表达直接暴露给教师和学生。

硬性要求：

- 希腊字母必须显示为数学符号：`θ`、`α`、`β`、`φ`、`ω`、`π`，不得在课堂可见区域出现 `theta`、`Theta`、`alpha`、`beta`、`phi`、`omega`、`pi` 等英文占位，除非是在代码文件名或开发说明中。
- 分式必须使用上下结构或等效的数学排版：例如 `π/2`、`2π/ω`、`-φ/ω`、`sin x / cos x` 在学生可见区域应排成上下分式或清晰的数学公式块；不得以横向纯文本斜杠作为主要展示方式。
- 公式中的乘法、指数、绝对值、区间、集合和条件必须接近教材书写：如 `2π`、`|A|`、`x ∈ R`、`k ∈ Z`、`[-1, 1]`，不得用 `2*pi`、`abs(A)`、`x in R` 替代。
- Applet、Manim、Diagnosis、平台资源卡、教师脚本和学生任务中的同一数学对象应使用统一符号；同一资源内不得混用 `theta` 与 `θ`、`pi/2` 与上下分式。
- 如果 HTML/CSS 原生排版不能稳定呈现上下分式，应在资源内实现轻量公式渲染组件或静态数学片段，而不是退回纯文本斜杠。
- 数学排版是质量闸门，不是视觉优化项。课堂可见公式未达标的资源不能建议进入 `math_review`、`browser_review`、`classroom_trial` 或更高状态。

审核时必须检查：

- 首屏、控制面板、图像标注、滑块标签、结论面板、弹窗、反馈语和导出视频画面是否存在 `theta`、`pi/2`、`sin x / cos x` 等纯文本表达。
- 分式在桌面、大屏、移动端和平台 iframe 中是否仍保持上下结构，不与按钮、图像或标注重叠。
- 屏幕阅读或无样式降级时，公式仍有可理解的 `aria-label` 或等价文本。

## Applet 设计规则

- 一个 Applet 只承载一个主要认知动作：比较、分解、变换、逼近、累积、缩放、投影或模拟。
- 初始界面只显示最小可理解对象，公式和结论应分步揭示。
- 所有表征必须联动，不允许只并排摆放图像、表格和公式。
- 颜色只用于数学含义，不作为装饰。
- 拖拽方向、滑块方向应和数学结构一致。
- 反馈必须解释规律，而不只是显示对错。
- 教师必须能控制节奏：暂停、重置、显示/隐藏标注、显示/隐藏结论。

## 自动校验

新增或修改课程图谱、Applet 资源包、Manim 资源包、Diagnosis 资源包后必须运行：

```bash
npm run validate:content
npm run generate:backlog
```

该命令会检查：

- Applet / Manim / Diagnosis metadata 是否符合对应 JSON Schema。
- 资源目录名是否与 `metadata.id` 一致。
- `metadata.curriculum.lesson_id` 是否存在于 `content/curriculum/index.yaml`。
- 已落地资源是否能与课程图谱中的 `digital_entry_points[].proposed_resource_id` 对齐。
- metadata 中声明的 README、脚本、任务、分镜、场景脚本、题组、评分规则、教师说明、审核记录等文件是否真实存在。
- Manim `video_ready` 资源是否存在 `dist/final/` 下的 `mp4`、`webm` 和 poster。
- `content/production/resource-backlog.json` 是否能从课程图谱和已落地资源包重新生成。

完整项目验证使用：

```bash
npm run verify
```

## 审核维度

- 数学准确性：定义域、边界条件、特殊情况、符号全部正确。
- 教学必要性：确实解决某个课时痛点。
- 交互有效性：学生操作会产生数学意义。
- 认知负荷：页面不过载，信息分步出现。
- 课堂可用性：大屏清晰，触控友好，低配置设备可运行。
- 版权合规：不复制教材正文、官方 PPT、教案或商业平台资源。
