## 目标

本轮不扩充课程图谱、不 scaffold 新资源，也不追求覆盖更多课时。目标是把已经实现的资源从 `self_checked_draft` 推进到更可信的审校状态，验证“数学审校 -> 课堂节奏试读 -> 浏览器/视频复核 -> review 记录”的质量线。

## 总控规则

- 每个新对话只审校一个资源，使用独立短分支或独立 worktree。
- 不修改 `content/curriculum/index.yaml`，不新增 `digital_entry_points`。
- 不提交 `content/production/resource-backlog.json`、`apps/web/src/data/workspace-data.json`、全局测试计数或总控状态文档；这些由总控合并后统一再生。
- 如果审校发现数学错误、符号显示问题、题目歧义或课堂节奏问题，可以直接修改该资源包内的源文件、脚本、题组、metadata 和 `review.md`。
- 如果没有代码或内容改动，也要把审校结论、证据、剩余风险写入该资源的 `review.md`。
- 每个资源至少运行 `npm run validate:content`；若修改了 HTML、Manim 场景、metadata 或题组，运行 `npm run verify`。

## 审校口径

### 数学

- 定义域统一为 `x != π/2 + kπ, k ∈ Z`。
- 渐近线统一为 `x = π/2 + kπ, k ∈ Z`。
- 周期统一为 `π`，理由可用 `tan(x + π) = tan x`。
- 单调性只能表述为在每个区间 `(-π/2 + kπ, π/2 + kπ)` 上递增，不能说在整个定义域上递增。
- 值域为 `R`，但课堂语言尽量避免不必要的极限术语；可用“函数值可以任意大/任意小”辅助解释。

### 显示与体验

- 所有 `π/2`、`-π/2`、`3π/2` 等课堂可见文本应使用符合数学语言的分式或清晰符号，不出现 `pi/2`、`Theta`、横向斜杠主导的表达。
- Applet 首屏不能因 iframe 高度、底部操作栏或浏览器缩放导致核心图像被截断。
- Manim 视频里的文字、公式、图像、渐近线和规则面板不能互相遮挡。
- Diagnosis 题干、选项和反馈中的一般式、开区间、周期和奇偶性表达保持一致。

## 总控合并后检查

三个审校分支完成后，总控集成时检查：

1. 每个资源的 `review.md` 是否写明审校证据，而不是只勾选清单。
2. 如果资源内容变更，metadata、教师脚本、学生任务、题组或分镜是否同步。
3. 是否有任何新对话误提交了全局生成文件；若有，总控统一再生。
4. 运行 `npm run generate:backlog`、`npm run generate:content` 和 `npm run verify`。
5. 根据审校结果决定是否把资源状态从 `self_checked_draft` 推进到更明确的 `math_reviewed` / `browser_reviewed` / `classroom_trial_ready` 等后续字段设计。
