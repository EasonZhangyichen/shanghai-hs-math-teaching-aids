## 交互稳定性

已复核以下交互，三种视口均稳定：

- 路径切换：`D → A → E`、`D → B → C → E`、`D → B → E` 均能切换 pressed 状态，并同步更新路径等式。
- 基向量切换：`AB / AC` 与 `AB / BC` 均能切换，并把表达更新到 `p = AB, r = BC` 口径。
- 典型分点：中位线型显示 `m = 1/2`、`n = 1/2`；非对称显示 `m = 0.65`、`n = 0.35`；靠近顶点显示 `m = 1/4`、`n = 3/4`。
- 滑块：手动设置到 `m = 0.8`、`n = 0.2` 后，读数、基向量表达和路径化简同步更新。
- 分步揭示：第 1 到第 4 步状态稳定；第 4 步能显示目标向量 `DE`；重置后恢复第 1 步、`AB / AC`、`D → A → E`、`m = 0.4`、`n = 0.65`。

## 数学表达审校记录

本轮按浏览器复核范围只记录风险，不修改资源包。

当前页面和文档中存在位置向量简写：

- `D = mp`
- `E = nq`
- 动态读数如 `D = 0.4p，E = 0.65q`

建议后续数学审校统一表达。若保留点名 `D`、`E`，需明确“以 `A` 为共同起点的位置向量”的语境；更稳妥的课堂写法是改为：

```text
AD = m AB
AE = n AC
DE = AE - AD
```

或在向量记号层面统一为 `\vec{AD} = m\vec{AB}`、`\vec{AE} = n\vec{AC}`。否则学生可能把点 `D`、`E` 与向量本身混读。

## 剩余风险

1. 平台 iframe 需要优先处理：要么提高 iframe 高度，要么压缩 Applet 首屏/右侧面板，让基向量切换至少能和路径按钮、滑块、读数同屏。
2. `1024x768` 平台页中 iframe 初始位置约在 top `5113`，教师从课时页进入真实课件的滚动成本过高。
3. 本轮为桌面 Chrome 自动化与 in-app Browser 冒烟，未覆盖真实教室触控屏、Safari、低配 Windows 教师机或投屏缩放。
4. `D = mp / E = nq` 属数学表达统一问题，需要后续数学审校或全局符号规范处理。
